  - 仓库/分支加载中遇到未授权时，增加连接校验与失效回收（`GET /integrations/scm/connections/validate` + revoke），并提示用户重新绑定。
  - 新增兼容模式：当后端暂不支持 `connections/validate/revoke` 时，前端回退为“仓库探测授权来源”（GitHub/GitLab/已记忆私有 GitLab），避免刷新后直接报“加载 SCM 授权状态失败”。
  - 兼容补丁：`GET /integrations/scm/connections` 返回 `400`（常见于旧后端参数校验）时，同样走回退探测流程，不再将其当作致命失败。
  - 兼容补丁：当后端返回 `{"error":"bad_request","message":"GitHub auth_mode 仅支持 github_app"}`（包括 `200+业务错误体` 与 `400`）时，前端识别为连接中心不兼容并回退；GitHub 请求同时携带 `auth_mode=github_app` 与 `github_auth_mode=github_app` 以兼容历史实现。
  - 兼容模式下断开行为降级为平台侧撤销提示（前端不再误发不可用 revoke 请求）。
  - 探测降噪补丁：兼容模式优先使用本地 provider hints 探测来源，避免在仅授权 GitHub 时重复请求 `provider=gitlab` 触发可预期的 `unauthorized` 噪声日志。
  - 新增协作约束：后端需保持 `connections / validate / revoke` 三接口可用；前端以“仓库所属来源”推导 `provider/gitlab_base_url`，不得回退为弹窗当前 provider。
