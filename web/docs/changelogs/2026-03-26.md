## 代码审查继续修复线程绑定收敛 (2026-03-26)

- **摘要**: 将代码审查的“继续修复”流程收敛到审查运行自身绑定的 `thread_id`，不再基于同仓库任务候选列表做线程选择。
- **原因**: 继续修复必须复用审查运行已绑定的线程，以共享同一套容器与 bootstrap 状态，避免创建新的继续目标。
- **影响**:
  - `src/hooks/use-portal-code-review-continuation.ts`: 改为直接读取 `selectedRun.thread_id`，并在跳转时按绑定线程生成 `/tasks/{thread_id}`。
  - `src/business/portal/portal-code-review-continue-fix-dialog.tsx`: 移除线程选择 UI，改为只展示绑定线程的只读上下文信息。
  - `test/hooks/use-portal-code-review-continuation.test.ts`: 补充线程 id 可用性、路由目标与 route state 传递的单元测试。
  - `test/business/portal/portal-code-review-continue-fix-dialog.test.ts`: 补充绑定线程解析与只读 UI 的测试。
