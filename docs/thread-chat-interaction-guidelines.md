# Thread Chat Interaction Guidelines

本文档约束任务详情页与线程聊天区在流式渲染、主动取消、工具回显场景下的交互行为，避免“状态收敛后 UI 仍停留在中间态”。

## 1. 回合锚点

- 一个用户回合从 `user` 消息开始，到下一条 `user` 消息前结束。
- “当前轮 AI 消息的末尾”指当前回合中最后一个可见的 AI 侧渲染块，而不是最后一个纯文本 `assistant` 节点。
- 若 assistant 文本后面仍跟随 tool/status/diff 卡片，复制、重试、状态提示等回合级操作必须挂在该回合最后一个可见块之后。

## 2. 流式与取消收敛

- `submitted` / `streaming` 阶段允许使用临时中的“响应中”锚点。
- 一旦用户主动取消、线程被中断、或流式结束，UI 必须在同一轮渲染内把锚点收敛到最终回合尾部。
- 不允许在流式结束后继续把交互按钮留在中途的 assistant 文本块下方。

## 3. 复制规则

- 复制内容来源始终取当前回合最后一个可复制 assistant 总结文本。
- 复制按钮的展示位置取当前回合最后一个可见 AI 块。
- 因此“内容来源”和“按钮挂载位置”可以不是同一条消息，这属于预期行为。

## 4. 实现建议

- 不要直接用“最后一条消息”推导回合级交互位置；取消后尾部常常停在 tool 行。
- 优先按“回合范围”计算交互锚点，再把具体按钮挂到该锚点对应的渲染项。
- 任何新增的回合级交互都应补测试，至少覆盖：
  - 正常流式完成
  - assistant 后仍有 tool 回显
  - 用户主动取消
