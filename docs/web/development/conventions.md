# 开发规范与技术约束 (Conventions)

本文件详细记录了 OpenWebPX UI 项目的架构约束与编码标准，作为 `AGENTS.md` 协议的补充。

## 1. 架构与路由约束
- **Provider 依赖顺序**: `ThreadProvider` -> `StreamProvider` -> `SidebarProvider`。
- **路由结构**:
  - `/login`, `/register` (Guest only)
  - `/` (Dashboard/Portal)
  - `/tasks/:id` (Task Detail)
  - `/settings` (Code Review & Profile)

## 2. 状态与加载规范
- **异步加载交互**:
  - 首次加载数据前必须显示 `loading`。
  - 仅在“加载完成且为空”时显示 `empty` 态。严禁空态闪烁。
- **状态优先级**: 在复杂页面（如 `TaskDetailPage`）中，加载态判定应聚合所有关键异步源。

## 3. 会话与流式渲染规范
- **流式同步**: 用户发送后，用户消息与“正在回复”状态必须同步出现。
- **工具链折叠**:
  - 默认仅展开“最新一轮”工具链。
  - 发送新消息后，待 AI 开始新一轮回复再折叠上一轮。
- **渲染稳定性**: 消息列表与工具项的 `key` 必须稳定（优先使用 `message.id`），禁止使用索引或长度。
- **复制按钮**: 回复未完成前，禁用当前轮次的复制按钮。

## 4. 组件分层阈值
- **页面容器 (`src/pages/*`)**: 超过 500 行或包含 >10 个 `useState` 时，必须拆分为业务组件或 Hook。
- **业务组件 (`src/business/*`)**: 单文件超过 300 行时需进一步拆分。

## 5. SCM 授权规范
- **真源原则**: 授权状态以 `/integrations/scm/connections` 接口返回为准。
- **聚合展示**: 仓库下拉列表应按来源（GitHub/GitLab）分组展示，互不干扰。
- **回退逻辑**: 后端接口 404/405 时，前端自动降级到探测模式。

## 6. Prompt 附件规范
- **类型白名单**: 仅支持文本、配置、表格与代码文件。
- **交互**: 文件被拒绝时必须给出明确 Toast 提示。
