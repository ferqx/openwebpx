# ADR 模板（Architecture / Product Decision Record）

> 文件命名建议：`docs/adr/ADR-YYYYMMDD-<short-title>.md`

## 1. 标题
一句话描述本次决策。

## 2. 状态
- Proposed / Accepted / Deprecated / Superseded

## 3. 背景
- 当前遇到的具体问题是什么？
- 业务目标是什么？
- 约束条件（技术栈、兼容、时效、成本）是什么？

## 4. 决策
- 本次最终采用的方案是什么？
- 涉及哪些边界（页面、业务组件、provider、接口）？

## 5. 备选方案
1. 方案 A：简述 + 优缺点
2. 方案 B：简述 + 优缺点
3. 方案 C：简述 + 优缺点

## 6. 决策理由
- 为什么当前方案更合适？
- 放弃其他方案的关键原因是什么？

## 7. 影响评估
- 正向影响：
- 负向影响：
- 风险点：
- 回滚策略：

## 8. 实施计划
1. 修改文件清单（页面容器/业务组件/公共组件/hook）
2. 分步骤实施
3. 验收标准

## 9. 验证记录
- 已执行检查：`pnpm lint` / `pnpm build` / 手工验证路径
- 结果：通过/未通过（注明原因）

## 10. 后续动作
- 是否需要补充 AGENTS.md 规范
- 是否需要追加监控、埋点、测试

## 示例（简版）
### 标题
任务详情与聊天页统一线程会话组件

### 状态
Accepted

### 背景
`task-detail.tsx` 与 `chat.tsx` 都有线程对话逻辑，重复实现导致行为不一致。

### 决策
抽离 `src/business/thread-chat/*` 公共业务组件与 `use-thread-chat` 业务 hook；页面仅负责 agent 配置与数据编排。

### 影响评估
- 正向：减少重复代码，统一交互行为
- 风险：抽离初期可能引入消息映射回归
- 回滚：保留原页面实现分支，必要时快速切回
