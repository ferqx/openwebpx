- **原因**: 在列表/详情两层视图已经建立后，继续保留多组筛选控件会让用户在进入页面时做过多判断；大多数场景只需要搜索和一个面向任务的快速筛选入口。
- **前端影响**:
  - [portal-code-review-list.tsx](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/web/src/business/portal/portal-code-review-list.tsx) 用单一 `快速筛选` 下拉取代独立的 `状态` 和 `模式` 过滤器，并去掉单独的“清除筛选”按钮。
  - 当前快速筛选覆盖的主场景包括：全部结果、待审批、分析中、已完成、失败、仅审查、自动修复。
- **测试**:
  - `pnpm --prefix web exec node --import tsx --test test/business/portal/portal-code-review-detail.test.ts test/business/portal/portal-code-review-list.test.tsx`
  - `pnpm --prefix web exec eslint src/business/portal/portal-code-review-list.tsx src/business/portal/portal-code-review-detail.tsx src/business/portal/portal-task-content.tsx test/business/portal/portal-code-review-list.test.tsx`

## 应用启动入口统一到 `app.main:app` (2026-03-22)

- **摘要**: 将本地脚本、docker compose 和开发文档中的后端启动入口统一收敛到 `app.main:app`，不再混用 `aegra_api.main:app`。
- **原因**: 既然 OpenWebPX 未来会把 `aegra` 依赖层剥离出去，当前继续把容器和本地启动绑定到 `aegra_api.main:app` 会放大迁移成本，也容易导致“本地跑的是一个入口，容器里跑的是另一个入口”的行为偏差。
- **后端影响**:
  - [run_server.py](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/run_server.py) 的 `uvicorn` 目标改为 `app.main:app`。
  - [docker-compose.yml](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/docker-compose.yml) 和 [docker-compose.prod.yml](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/docker-compose.prod.yml) 的后端服务启动目标统一改为 `app.main:app`。
  - 开发 compose 里的服务名从 `aegra` 调整为 `api`，前端容器内的 `VITE_API_URL` 与 `depends_on` 也同步对齐。
- **文档影响**:
  - [CLAUDE.md](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/CLAUDE.md) 明确 `make run` 实际启动的是 `app.main:app`。
  - [architecture.md](/Users/chenchao/.codex/worktrees/4f3e/openwebpx/docs/architecture.md) 的容器服务命名同步从 `aegra` 更新为 `api`。
- **测试**:
  - `uv run pytest tests/test_server_entrypoints.py -q`
  - `rg -n "aegra_api\\.main:app|uv run aegra dev" run_server.py docker-compose.yml docker-compose.prod.yml CLAUDE.md docs -S`
  - `rg -n "app.main:app" run_server.py docker-compose.yml docker-compose.prod.yml CLAUDE.md docs -S`
